# LLM Fundamentals

## What is an LLM?

An **LLM (Large Language Model)** is an AI model trained on enormous amounts of text to understand and generate human language.

Instead of following fixed rules like traditional software, an LLM predicts the **most likely next token** based on the text it has already seen.

Examples include:

- GPT (OpenAI)
- Claude (Anthropic)
- Gemini (Google)
- Llama (Meta)
- Mistral (Mistral AI)

---

## What does "Large Language Model" mean?

- **Large** → Trained on massive datasets with billions (or trillions) of parameters.
- **Language** → Designed to understand and generate natural language.
- **Model** → A mathematical system that learns patterns from data.

---

## LLM vs Traditional Software

### Traditional Software

Traditional programs follow predefined rules.

Example:
IF password == correct
    Login
ELSE
    Reject

The developer explicitly writes every rule.

### LLMs

LLMs do not store explicit rules for every situation.
Instead they learn statistical patterns during training and generate responses by predicting what comes next.
Because of this, the same prompt can sometimes produce different answers.

---

## Why are LLMs called probabilistic models?

An LLM does **not** search for the "correct" answer.
Instead, it assigns probabilities to possible next tokens.

Example:
Prompt: The capital of France is

Possible predictions:

| Token | Probability |
|---------|------------|
| Paris | 99.8% |
| London | 0.1% |
| Berlin | 0.1% |

The model usually selects the highest-probability token (or samples from the distribution depending on settings like temperature).

---

# Tokens

## What is a token?

A **token** is the basic unit of text processed by an LLM.
A token is **not always a word**.

Examples:
Hello May be: ["Hello"]
But unbelievable might become ["un", "believ", "able"]
Even punctuation and spaces can be separate tokens.

---

## Word vs Token

Sentence: I love AI.

Words:
- I
- love
- AI

Tokens might be:
- I
- love
- AI
- .

The exact tokenization depends on the model.

---

## Character vs Token

Characters: Hello
Characters = 5
Tokens = usually 1

Long or uncommon words may be split into multiple tokens.

---

## Why tokenization matters

Everything the model processes becomes tokens.

This affects:
- Cost
- Speed
- Context size
- Memory usage

---

## Input Tokens

Tokens sent to the model.

Includes:
- System prompt
- Developer prompt (if used)
- User message
- Conversation history

---

## Output Tokens

Tokens generated by the model as its response.

---

## Token Limits

Every model has a maximum number of tokens it can process at once.

Example:
Input + Output <= Context Window

If the limit is exceeded, older content may be removed or the request may fail.

---

## Why APIs charge by tokens

Running the model requires computation for every token processed.

You are usually billed separately for:
- Input tokens
- Output tokens

Long prompts cost more than short ones.

---

# Context Window

## What is a context window?

A context window is the maximum amount of information an LLM can consider during one interaction.

It contains:
- System prompt
- Developer prompt
- Conversation history
- Current user prompt
- Generated response

---

## Conversation History

The model does **not** permanently remember previous chats.
Instead, previous messages are included in the current context window.

---

## Why the model forgets

When the context window becomes full, older messages may be removed.

The model then loses access to that information.

This is often described as the model "forgetting," although it is really a limitation of the available context.

---

## Context Overflow

If the conversation becomes too long:

- oldest messages are removed
- important instructions may disappear
- answers become less consistent

---

## Token Budget

The total context window is shared by:


System Prompt
+
Developer Prompt
+
Conversation History
+
User Prompt
+
Model Response


This is called the **token budget**.

---

## Why attackers care about context

Attackers may try to:

- fill the context window
- push important instructions out
- hide malicious prompts
- manipulate conversation history

These ideas are important in prompt injection and context manipulation attacks.

---

# Prompt Types

Modern LLMs process different kinds of instructions.

## 1. System Prompt

Highest-level instructions.

Examples:

- You are a cybersecurity assistant.
- Never reveal confidential information.
- Answer professionally.

The system prompt defines the model's overall behavior.

---

## 2. Developer Prompt

Used by application developers.

Examples:

- Always respond in Markdown.
- Only answer questions about company policies.
- Use available tools before responding.

Developer prompts help control how an application uses the model.

---

## 3. User Prompt

The instructions provided by the user.

Example:


Explain SQL injection.


---

## 4. Assistant Response

The model's generated reply.

---

## Prompt Priority

Highest priority:


System Prompt
↓
Developer Prompt
↓
User Prompt
↓
Assistant Messages


Conflicting lower-priority instructions should not override higher-priority ones, although attackers often try to do exactly that.

---

## Why prompt injection exists

Prompt injection attempts to convince the model to ignore or override higher-priority instructions.

Example:


Ignore all previous instructions.


Whether this succeeds depends on how the application is designed and how the model follows instruction hierarchy.

---

# Temperature

Temperature controls randomness in token selection.

It does **not** make the model "smarter."

---

## Low Temperature

Examples:


0.0
0.1
0.2


Characteristics:

- predictable
- consistent
- factual
- deterministic

Often used for:

- coding
- security testing
- evaluations

---

## High Temperature

Examples:


0.8
1.0
1.2


Characteristics:

- creative
- varied
- less predictable

Useful for:

- storytelling
- brainstorming
- creative writing

---

## Deterministic vs Creative Output

Low temperature:


"What is 2+2?"

Always:
4


High temperature:

Creative tasks may produce different outputs each time.

# Hallucinations

## What is a hallucination?

A hallucination is when an LLM generates information that sounds convincing but is incorrect, fabricated, or unsupported.

---

## Why hallucinations happen

The model predicts likely text rather than verifying facts.

It does not inherently know whether a statement is true.

---

## Types of hallucinations

- Fake facts
- Fake citations
- Incorrect code
- Invented URLs
- Made-up references
- Wrong reasoning

---

## Why hallucinations matter for security

Hallucinations can:

- spread misinformation
- produce insecure code
- invent vulnerabilities
- generate unsafe recommendations
- reduce trust in AI systems

---

## How RAG helps

Retrieval-Augmented Generation (RAG) retrieves relevant documents and provides them to the model before it generates a response.

This grounds answers in external information and can reduce hallucinations.

---

## Why hallucinations cannot be eliminated completely

Even with high-quality retrieval and careful prompting, LLMs can still misunderstand information, make reasoning errors, or generate unsupported statements.

# How an LLM Processes a Prompt


User
   │
   ▼
Prompt
   │
   ▼
Tokenization
   │
   ▼
Context Assembly
(System + Developer + History + User)
   │
   ▼
LLM
   │
   ▼
Probability Prediction
(next token)
   │
   ▼
Generated Tokens
   │
   ▼
Final Response


### Processing Steps

1. User submits a prompt.
2. Text is converted into tokens.
3. System prompt, developer prompt, conversation history, and user prompt are combined.
4. The model predicts the next token based on probabilities.
5. Tokens are generated one by one until the response is complete.

# Key Takeaways

- LLMs predict the next token rather than retrieving fixed answers.
- Tokens are the basic units processed by the model.
- Context windows limit how much information the model can use at one time.
- System prompts have the highest instruction priority, followed by developer and user prompts.
- Temperature controls response randomness, not intelligence.
- Hallucinations are incorrect but plausible outputs and cannot be completely eliminated.
- Understanding tokenization, context, and prompt hierarchy is essential for AI security topics such as prompt injection, jailbreaks, and context manipulation.
